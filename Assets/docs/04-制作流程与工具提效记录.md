### 1.4 流程层面的提效原则

1. **数据先行**：功能先定数据结构 + 接口（写在 TDD），再写实现。
2. **逻辑一份，壳两份**：编辑器做双形态时，核心逻辑只写一份，避免两边行为漂移。
3. **能复用就不重写**：UI 工具链直接搬旧作品，省下的时间给玩法打磨。
4. **求快不求美**：美术未到位不影响逻辑；逻辑跑通再换皮。
5. **小步提交**：每个 commit ≤ 1 个功能，编译通过再提交。
6. **AI 当 pair**：不确定的 API / 算法直接问，让 AI 出多个候选方案对比。

## 2. 决策日志 ADR（Architecture Decision Records）

> 每个大决策一行"为什么"，方便评审快速读。**被推翻的决策保留并划线**，能看出思考过程。

| # | 决策 | 取舍 | 结论 | 版本 |
|---|---|---|---|---|
| 01 | 静态 / 动态分层（`LevelData` vs `WorldState`） | 关卡 JSON 极简 vs 一把梭 | 取：**分层**（更易做撤销 + 编辑器） | v1 |
| 02 | 撤销栈存全量快照 | 全量 vs 差分 | 取：**全量**（W、H ≤ 20 时可忽略体积） | v1 |
| 03 | 邪恶推箱人 = 「玩家输入的镜像」 | 真 AI 寻路 vs 机械反射 | 取：**机械反射**（题目字面意思 + 调试简单） | v1 |
| 04 | ~~玩家撞墙不入撤销栈~~ | ~~一律入栈 vs 撞墙不入~~ | ❌ **已被 ADR 08 推翻** | v1→v2 |
| 05 | ~~求解器 = 简单 BFS + 死锁剪枝~~ | ~~JSK 移植 vs 简单 BFS~~ | ❌ **已被 ADR 12 取代**（升级为混合策略） | v1→v3 |
| 06 | 美术 = AI 生图 + 占位兜底 | 100% AI vs 100% 占位 | 取：**混合**（关键角色 + UI 用 AI，其余可占位） | v1 |
| 07 | 关卡格式 = JSON | JSON vs ScriptableObject | 取：**JSON**（Git diff 友好 + 编辑器直存） | v1 |
| 08 | **敌人执行与玩家移动解耦** | 玩家撞墙则敌人不动 vs 敌人无条件尝试移动 | 取：**敌人无条件动**（用户拍板） | v2 |
| 09 | 入栈判定 = 世界状态哈希变化 | 按"玩家是否移动" vs 按"世界是否变化" | 取：**世界哈希变化**（四种组合都正确覆盖） | v2 |
| 10 | **关卡编辑器双形态** | 只做游戏内 vs 只做 Editor 插件 vs 双形态 | 取：**双形态 + 共用核心** —— Editor 插件便于开发期批量做关（可接 Unity Undo），游戏内便于演示与 UGC；核心逻辑只写一份防漂移 | v3 |
| 11 | **UI 走 UI Builder 产出** | 手写 uGUI vs 工具排版导入 | 取：**工具排版导入** —— 多比例适配在工具里切下拉即可预览，且复用既有作品，省下时间给玩法 | v3 |
| 12 | **求解器 = 正向 BFS + 反向 BFS 混合** | 单一 BFS vs 混合 | 取：**按箱子数切换**（≤8 正向，9~15 反向）；拓展模式只走正向。正向 P0、反向 P1，做不完可砍 | v3 |
| 13 | **移动端适配范围** | 完整移植 vs 只适配游玩 | 取：**只适配游玩**（棋盘等比 + HUD 贴边 + SafeArea + 滑动输入）；移动端不做关卡编辑器与求解 | v3 |
| 14 | **撤销不减步数** | 撤销减步 vs 不减 | 取：**不减** —— 否则可反复推了又撤销把步数刷成 0；撤销次数单独统计 | v3 |
| 15 | 拓展模式不计敌人步数 | 计 vs 不计 | 取：**不计** —— 敌人移动已隐含在玩家每步里，单独统计是噪音 | v3 |
| 16 | **关卡来源分类（`source` 字段）** | 全混一个列表 vs 分类标签 | 取：**分类**（内置 / custom / imported）—— 155 关导入后不分类没法浏览；选关页按标签 + 搜索 + 分页 | v4 |
| 17 | **「校验」≠「有解」，两段式** | 只做结构校验 vs 结构 + 真求解 | 取：**结构校验通过后再跑真求解器** —— 用户把"校验通过"当"有解"用，糊弄会砸口碑；求解器复用运行时 `Step`，障碍语义一致 | v4 |
| 18 | **一个 `.cs` 文件只放一个 `MonoBehaviour`** | 多类共文件 vs 一类一文件 | 取：**一类一文件** —— GUID 只可靠解析"类名=文件名"的主类，共文件导致 `UIBuilderDoc` 全线 missing script | v4 |
| 19 | **编辑态预览与 Play 共用缩放引擎** | 场景静态 Scaler vs 编辑器脚本接管 | 取：**编辑器脚本每帧按 GameView 真实分辨率接管 `scaleFactor`**（Constant 模式），预览与 Play 完全一致；尺寸来源必须反射 `GameView.targetSize`，用 `Screen.width` 会随鼠标在视口间移动而"飘" | v4 |
| 20 | **关卡数据坐标系 y 向上（权威）** | 编辑器 y 向下（文本直觉） vs 游戏渲染 y 向上 | 取：**全链路 y 向上** —— 数据、游戏渲染、双编辑器渲染统一，导出关卡方向与预览 100% 一致；导入器负责把 XSB 文本行序翻转 | v4 |
| 21 | **局内素材程序化兜底** | 素材缺失报错 vs 回退色块 | 取：**运行时加载失败自动回退程序化色块** —— 美术与逻辑彻底解耦，删图游戏照跑 | v4 |
